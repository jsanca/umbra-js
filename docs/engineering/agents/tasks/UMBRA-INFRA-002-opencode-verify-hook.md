# UMBRA-INFRA-002 — OpenCode Verify Hook — Integration Notes

Status: **PROPOSED — NOT ACTIVE**.

The verification pipeline (`npm run verify`, alias of `bash scripts/umbra-verify.sh`) is in place and confirmed working. Hook integration into the OpenCode lifecycle is not active because wiring requires changes that the current slice explicitly disallows. See "Why PROPOSED, not ACTIVE" below.

## Manual command (active and supported)

```bash
bash scripts/umbra-verify.sh
# or via npm:
npm run verify
```

`npm run verify` writes a Markdown report under `docs/engineering/agents/reports/hooks/umbra-verify-<timestamp>.md` and exits 0 only if every required command passed. The optional dev-server smoke is opt-in via `--with-dev-smoke` / `npm run verify:smoke`.

## Why PROPOSED, not ACTIVE

The UMBRA-INFRA-001 notes documented an unresolved question: does OpenCode expose a project-local hook mechanism in this environment? UMBRA-INFRA-002 resolved that question with new evidence:

1. **OpenCode DOES expose a project-local hook mechanism.** Per the `customize-opencode` skill, OpenCode auto-discovers plugins in `.opencode/plugin/<file>.{ts,js}`. Each plugin exports a function returning a `Hooks` object with callbacks like `event(input)`, `tool.execute.before`, `tool.execute.after`, `experimental.text.complete`. None of these is named `session.idle`; the `hooks` field in `opencode.json` is **not** a valid OpenCode config shape — that was an INFRA-001 error corrected below.

2. **Creating `.opencode/` in this repo directly contradicts AGENTS.md.** AGENTS.md "Repo-specific gotchas" line: "No `opencode.json` exists at the repo root; tool-level config lives in user/global config, not in this repo." This is explicit project policy. Wiring a project-local plugin would require creating `.opencode/`, which violates it.

3. **Global user config modification is forbidden by both this task brief and the INFRA-001 task brief.** Hooks cannot be wired via `~/.config/opencode/opencode.jsonc` because the user-level config is currently empty (only `$schema`) and modifying it requires explicit human approval, which is not in scope for this slice.

4. **Adding a new package dependency is forbidden.** Writing a typed OpenCode plugin requires `@opencode-ai/plugin` (for the `Plugin` type). The task brief explicitly forbids adding dependencies. A pure-JS plugin would avoid the type dep but still requires `.opencode/` to exist in the repo, which violates AGENTS.md.

5. **Automatic hook execution cannot be observed from a single agent session.** The task brief requires observed automatic execution before claiming ACTIVE. The `customize-opencode` skill says config-time files require a manual OpenCode restart to load. I cannot restart OpenCode from inside this session, so observation is impossible here. ACTIVE is therefore unreachable in this slice regardless of which path is taken.

## Corrected hook surface (UMBRA-INFRA-002 Sketch C — proposed, not created)

OpenCode plugins are auto-discovered from `.opencode/plugin/<file>.{ts,js}`. The exported function receives a `PluginInput` (`{ client, project, directory, $ }`) and returns a `Hooks` object. The hook surface that could plausibly fit this use case is:

- `event(input)` — every bus event. The skill does not enumerate which event types exist; `session.idle` is not documented. Cannot target a specific event without empirical enumeration.
- `experimental.text.complete` — fires when a text response completes. Marked experimental. Could approximate "end of agent turn" but the cost of running `npm run verify` per turn (audit + typecheck + tests + build) is too high to be a per-event hook.
- `tool.execute.after` — fires after every tool call. Far too frequent.

No documented hook fits "stop / session-idle / post-iteration" precisely. A correct Sketch C would therefore be:

```js
// .opencode/plugin/umbra-verify.js
//
// PROPOSED — NOT CREATED. This file would create project-local `.opencode/`
// in this repo, which contradicts AGENTS.md. Recorded here as the corrected
// shape after the INFRA-001 sketch was found to be invalid.
//
// Once AGENTS.md is amended to permit project-local `.opencode/`, this file
// could be created and OpenCode restarted to load it. Until then, do not
// create this file.

export default async ({ $ }) => {
  return {
    "experimental.text.complete": async () => {
      // Spawn the verification pipeline without blocking the agent turn.
      // Each run writes to docs/engineering/agents/reports/hooks/.
      $`bash scripts/umbra-verify.sh`.catch(() => {});
    },
  };
};
```

Why this sketch and not `event(input)`:

- `event` fires on every bus event; running `npm run verify` per event is excessive and would loop on events generated by the verify pipeline itself if it ever touched OpenCode tooling.
- `experimental.text.complete` is the closest fit. It is marked experimental; treat the sketch as conditional on that surface remaining stable.
- A `$`-spawned child process keeps the agent turn responsive while the verification runs in the background. The script's report file is the durable evidence.

Why this is still PROPOSED and not ACTIVE:

- The file is not created. AGENTS.md policy blocks it.
- ACTIVE would require (a) amending AGENTS.md, (b) writing this file, (c) the user restarting OpenCode, (d) an empirical run that observes the report file appearing in `docs/engineering/agents/reports/hooks/` after an agent turn. None of those steps can be performed inside this slice.

## Path to ACTIVE (future)

If the project later wants ACTIVE status, the following steps are required, in order, with explicit human approval at each step:

1. **Amend AGENTS.md** to permit project-local `.opencode/plugin/` (or amend it to direct that hook integration must be at the user/global level — choose one). Either way, the policy must explicitly state where hooks live.
2. **Choose the hook target.** Either `experimental.text.complete` (per-turn, may be excessive) or wait for OpenCode to expose a stable `session.idle`-equivalent event.
3. **Create the file.** Either the Sketch C above or an equivalent (typed or pure JS).
4. **Restart OpenCode.** Required by `customize-opencode`: "After saving changes to `opencode.json`, an agent file, a skill, a plugin, or any other config-time file, tell the user to quit and restart opencode for the changes to take effect."
5. **Run a controlled iteration** that exercises the hook and observe that a new `umbra-verify-<timestamp>.md` appears in `docs/engineering/agents/reports/hooks/`.
6. **Update this notes file** to mark the proposal ACTIVE and link the observed report.

Each of those steps is outside the scope of this slice.
