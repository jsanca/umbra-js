# UMBRA-S1-001 — TypeScript + Vite Baseline — Report

## Status

Complete

## Objective

Establish a reproducible minimal browser baseline: manifest, TypeScript/Vite configuration, browser entry page, development/build/test commands, and a justified minimal test setup. Explicitly out of scope: UI shell, Canvas output, renderer, ray-tracing features, and optional dependencies.

Task contract: [S1-001 in the slice plan](../tasks/umbra-sprint-1-slices.md).

## Summary

Created a clean TypeScript + Vite + Vitest baseline from the empty repository. Three direct devDependencies are declared, each justified below. The baseline produces a runnable browser app that mounts `<main id="app">` and writes a placeholder string, has a passing typecheck, passing tests, and a clean production build. ADR-002 boundaries are preserved — no source under `src/` references DOM, Canvas, Vite, or UI types *into* the rendering math, because no rendering math exists yet; the boundary mapping below reserves directories for S1-002 onward.

## Files Changed

- `package.json` — manifest with `dev`, `build`, `preview`, `test`, `test:run`, and `typecheck` scripts and three devDependencies.
- `tsconfig.json` — root references file pointing at app and node configs.
- `tsconfig.app.json` — strict TypeScript for `src/` (`ES2022`, `DOM`, `DOM.Iterable`, `verbatimModuleSyntax`, `noEmit`).

- `index.html` — Vite entry HTML mounting `<main id="app">` and loading `src/main.ts`.
- `src/main.ts` — baseline entry that writes "Umbra baseline ready." into the mount point.
- `src/baseline.test.ts` — minimal Vitest smoke test asserting the test runner and source tree layout.
- `package-lock.json` — generated by `npm install`; 47 packages, 0 vulnerabilities.

No files under `docs/` or `.osk/` were modified. No source work beyond baseline bootstrap was performed.

### ADR-002 boundary mapping (proposed for S1-002 authorization)

ADR-002 separates the pure rendering core from the Canvas output adapter and the render controller. The chosen folder structure reserves these seams without yet placing rendering code anywhere. Slice 1 only sets up the workspace; it does not commit to a final directory name. The mapping below is a proposal that S1-002 can ratify or revise.

| Planned ADR-002 layer | Reserved path | Current contents | Notes |
| --- | --- | --- | --- |
| Pure rendering core | `src/core/` | empty | Strict `noUncheckedSideEffectImports`, `verbatimModuleSyntax`, and the absence of any DOM/Canvas reference in `tsconfig.app.json` keep this layer importable into a pure Node test runner with no browser shim. S1-004 (Vec3/Ray) will be the first module here. |
| Render controller | `src/controller/` | empty | Owns the fixed-scene request-to-buffer orchestration; the only layer permitted to depend on both core and adapter values. S1-003 (Canvas viewport + pixel writer) and S1-006 (background gradient) will land here. |
| Canvas output adapter | `src/canvas/` | empty | The only layer that may call `CanvasRenderingContext2D` or browser-only APIs. S1-003 lands here. |
| Diagnostics adapter | `src/diagnostics/` | empty | Lightweight seam for status / dimensions / render time. S1-003 lands here. |
| UI shell | `src/ui/` | empty | Holds DOM-only structure; S1-002 lands here. |
| Browser entry | `src/main.ts`, `index.html` | present | Wires the UI shell into the page. S1-002 will replace the placeholder text. |
| Test layer | `src/**/*.test.ts` | `src/baseline.test.ts` | Vitest with `environment: 'node'` for this slice; S1-002 will introduce `environment: 'jsdom'` (or Vitest browser mode) for DOM tests, and S1-003 will add a focused browser test for Canvas image data. |

Because S1-001 ships no rendering code, the ADR-002 boundary is *preserved by absence* and *prepared for* by the strict TypeScript settings (no implicit DOM types beyond what the browser entry needs). A reviewer running `tsc --noEmit` on this slice cannot identify a browser-API leak because none was written.

### Pre-approved scope — confirmed respected

The S1-001 task lists explicit non-goals: UI shell, Canvas output, renderer, and optional dependencies. None of these are present. The only DOM-touching code in this slice is the placeholder write in `src/main.ts`, which is a browser entry concern, not a renderer or UI shell.

## Limitations

- **No browser automation test yet.** Vitest is configured with `environment: 'node'` only. Browser-environment tests for S1-002 (DOM smoke) and S1-003 (Canvas image data) are intentionally deferred to those slices and are listed under Open Follow-Up.
- **No typecheck watch script.** Only `npm run typecheck` (one-shot) is wired. A `typecheck:watch` script can be added if needed; it was not in scope.
- **Vite dev server binds to `[::1]` only on this machine.** Local curls used `http://localhost:5173/` (which resolves to IPv6 `::1` here). `http://127.0.0.1:5173/` returned connection refused during validation. This is the Vite default for the IPv6-resolving host environment in which validation ran; reviewers on IPv4-only hosts may see the server on `127.0.0.1`. No code change is required; the `--host` flag can be passed to `vite` if exposure is desired.
- **No coverage, lint, or formatter were added.** Sprint 1 does not require them; S1-002 / S1-003 may add them if the reviewer requests, but this slice did not preempt that decision.
- **`.gitignore` was not modified.** The existing rules already cover `node_modules`, `dist`, `dist-ssr`, and editor metadata. Vitest's cache and TypeScript's `tsBuildInfo` files are placed under `node_modules/.tmp/` by configuration and therefore covered by the existing `node_modules` rule.

## Open Follow-Up

- S1-002 must ratify or revise the boundary mapping above; the directory names `core/`, `controller/`, `canvas/`, `diagnostics/`, `ui/` are reserved but not yet authoritative.
- S1-002 should add Vitest `environment: 'jsdom'` (or switch the relevant suite to Vitest browser mode) to enable DOM/UI smoke tests for AC-PROD-001 / AC-PROD-003 / AC-PROD-004 and TC-S1-002..004.
- S1-003 should add a browser test that asserts non-empty Canvas image data for TC-S1-011.
- A `typecheck:watch` script is optional and can be added in a later slice if requested.
- The `dev` script's default binding behavior should be confirmed against the reviewer's host environment; if IPv4 exposure is needed, the `vite` invocation can be changed to `vite --host 127.0.0.1`.
