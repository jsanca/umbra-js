# UMBRA-INFRA-001 — OpenCode Verification Hook — Report

## Status

Complete (with one explicit scope-limit: hook integration is **proposed, not active**).

## Objective

Create a deterministic local verification pipeline that can be run after each OpenCode agent iteration and produce a durable Markdown report with command output and a final PASS/FAIL status. Wire it as a stop/session-idle/post-iteration hook if the local OpenCode setup supports it; otherwise, do not fake it — document the manual command and a clearly-marked proposed hook configuration.

Task contract: [UMBRA-INFRA-001 hook notes](../tasks/UMBRA-INFRA-001-opencode-hook-notes.md).

## Summary

Created `scripts/umbra-verify.sh`, a self-contained POSIX bash script that runs the standard Umbra pre-iteration validation commands (`npm audit signatures`, `npm audit`, `npm run typecheck`, `npm run test:run`, `npm run build`), captures every command's stdout + stderr, records the working tree status / branch / commit SHA, and writes a Markdown report under `docs/engineering/agents/reports/hooks/umbra-verify-<timestamp>.md`. The script records every command regardless of individual failure (fail-**soft**) and exits 0 only if every required command passed (fail-**hard** at the aggregate). Two npm aliases (`verify`, `verify:smoke`) were added; no package dependencies were added.

Hook integration is **proposed, not active**: investigation showed no project-level hook mechanism exists in this environment and no user-level wiring can be done without violating the task's stop conditions. The hook notes file documents the manual command and a sketched project-level proposal that explicitly says "do not create without authorization."

The script was run as part of this slice: exit `0`, report at `docs/engineering/agents/reports/hooks/umbra-verify-20260828T200019Z.md`, final status `PASS`.

## Assumptions

- The local environment has `bash`, `git`, `curl`, `date`, `mktemp`, `sed`, `kill`, `wait` available on `PATH`. All are part of macOS's default userland and standard Linux distributions.
- The repository is a git working tree (so `git rev-parse` etc. succeed). The script falls back to `unknown` if `git rev-parse` fails, but the report's status block will read `(unavailable)` in that case.
- The slice handoff for S1-003 will use `bash scripts/umbra-verify.sh` (or `npm run verify`) as its TC-S1-001 evidence in addition to the per-command output captured inline in the slice report.

## Limitations

- The generated report is committed to the repository by default (the directory is intentionally not `.gitignore`'d). This is the project's pattern for durable evidence under `docs/engineering/agents/reports/`, but it does mean every verification run produces a tracked file. If a reviewer prefers the hook reports not be tracked, add `docs/engineering/agents/reports/hooks/` to `.gitignore`; this slice deliberately did **not** make that change.
- The `--with-dev-smoke` flag polls `curl` once per second for up to 8 seconds against `http://localhost:5173/`. On hosts where Vite defaults to IPv6 (the G1 Observation 3 platform note), the curl must use the IPv6-resolved `localhost` rather than `127.0.0.1`. The smoke uses `http://localhost:5173/` to match the platform note; on IPv4-only hosts this may need a future tweak.
- The script does not currently upload or publish the report anywhere — it only writes it to the repo. A future slice could add a hook that opens the report in the user's editor.
- No historical run aggregation. Each run produces a self-contained file with its own timestamp. If the project later needs cross-run trends, a small aggregator script can fold `docs/engineering/agents/reports/hooks/*.md` into a JSON index.

## Open Follow-Up

- If a future OpenCode version publishes a stable `hooks.session.idle` (or equivalent) project-level hook event, ratify the AGENTS.md policy, then implement Sketch A from the hook notes file.
- If the project later wants zero-dependency verification on machines without `bash` (e.g., Windows-only dev), port the script to a cross-shell language (TypeScript via `tsx`, called by `npm run verify`). Out of scope for this slice because no `bash`-less requirement was stated.
- If proportional screenshots become a per-iteration requirement (per [Sprint 1 verification strategy](../umbra-verification-strategy.md) "TC-S1-002..004 … proportionate screenshot"), a `--with-screenshot` flag could be added that wraps the dev-smoke with a Playwright capture. Out of scope here because no Playwright dependency may be added under the task's stop condition.
- A future slice could add a `verify:ci` alias that fails fast on the first failure (sets `-e`) for CI environments where recording all outputs is unnecessary. Not added speculatively.
